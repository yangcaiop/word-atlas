# 多用户和数据同步

文档状态：已开发。按用户指定的 MySQL、自动同步和退出清空规则实现；部署时需要配置数据库连接与 API 代理。

## 1. 用户需求

1. 使用 Express 实现最简单的用户名、密码注册与登录，只提供注册、登录、退出登录三个账号功能。
2. 未登录也能正常学习，数据保存在本地。
3. 注册新账号时，把当前本地数据同步到远程；登录已有账号时，用远程数据覆盖当前本地数据，不上传登录前的本地数据。
4. 登录后，学习数据变化自动上传到远程，同时保留手动“从远程获取”。
5. 退出登录后清空当前进度，以空白游客数据重新开始，不恢复登录前的游客进度。
6. 不需要邮箱、验证码、忘记密码或密码找回功能。

### 2.2 目标流程

| 场景           | 数据流向                       | 完成后的状态                                               |
| -------------- | ------------------------------ | ---------------------------------------------------------- |
| 游客使用       | 操作 → 本地保存                | 不请求用户数据上传接口，可继续离线学习。                   |
| 注册新账号     | 当前游客快照 → 新账号远程数据  | 自动登录；已有学习成果成为该账号的初始数据。               |
| 登录已有账号   | 远程快照 → 当前本地进度        | 远程数据成为本次学习的起点，登录前的数据不参与上传或合并。 |
| 登录后学习     | 本地立即保存 → 自动上传        | 同时保留本地可用性和远程副本。                             |
| 手动从远程获取 | 远程快照 → 当前本地进度        | 使用远程内容替换本地，之后继续自动上传新变更。             |
| 退出登录       | 停止同步 → 注销会话 → 清空进度 | 进入空白游客模式，远程数据保留。                           |

## 3. 实现范围

### 3.1 本期需要实现

- 客户端：在“我的”页提供账号入口，注册和登录只填写用户名、密码；登录后显示用户名、同步状态、“从远程获取”和“退出登录”。上传失败时提供重试入口。
- 登录和注册使用视口居中弹窗，桌面和手机均保持四周留白；弹窗挂载到 `document.body`，不受页面动画、滚动位置或父容器尺寸影响，内容超高时在弹窗内滚动。
- 服务端：注册、登录、退出、查询当前登录状态、获取当前用户数据、上传当前用户数据。
- 注册自动迁移游客数据；登录已有账号使用远程覆盖；登录后自动上传；退出后清空进度。
- 保留现有游客学习、本地保存和备份能力。
- 处理请求失败、登录失效、账号切换、旧版本上传和 API 缓存，保证数据不会跨账号使用。

### 3.2 本期最小边界

- 首期只同步公开词库 `word-atlas-open` 的用户数据。本机私有词库和 `/local/` 媒体继续只在本机使用。
- 同步学习记录与用户偏好，采用整份 JSON 快照，不增加逐词事件表、增量协议或后台任务队列。
- 保留当前设备的活动学习会话，不实现跨设备继续同一道题。
- 不做自动合并、实时推送、自动轮询远程数据、多端协同编辑或历史版本恢复。
- 不增加第三方登录、改密、找回密码、个人资料、头像、角色权限或账号管理后台。

## 4. 需求规则

### 4.1 游客与已有本地数据

- 未登录时，学习流程和本地保存继续工作；远程服务不可用不影响游客使用。
- 新用户默认暗色主题、美式发音、A1 起点；首次引导默认选中 A1，已有本地或远程偏好继续按保存值恢复。
- 升级时把现有无用户维度的本地数据视为游客数据，不自动创建账号或上传。
- 本地进度按“游客或用户 ID + 词库 ID”区分；用户名仅作显示和登录，不作为数据归属主键。
- 登录成功、远程获取成功后，替换内存状态和对应本地持久化数据，不能只更新页面显示。
- 账号切换通过先退出、再登录完成；旧账号的请求结果不得写入新账号或游客状态。

### 4.2 注册新账号

- 已确定：注册使用用户名、密码；注册成功自动登录，并上传注册前的当前游客数据。
- 把“创建账号、初始化远程快照、建立登录会话”放在同一次服务端事务中，避免账号创建成功但初始数据没有保存。
- 注册期间固定待迁移快照，暂时禁止修改学习数据，避免注册请求过程中的新进度遗漏。
- 用户名重复时注册失败，保持游客身份和本地数据，不能顺势把游客数据上传到已存在的账号。
- 网络失败或响应丢失时保留游客数据，不提前清空。若账号实际已创建，用户再次登录可取回已随账号保存的初始快照。

### 4.3 登录已有账号

- 已确定：登录已有账号使用远程数据覆盖当前本地数据，禁止把登录前的游客或账号缓存上传到远程。
- 登录接口直接返回用户信息和远程快照；收到完整且有效的结果后，才切换客户端身份、替换本地数据并启用自动上传。
- “身份认证成功、数据仍在加载”期间不允许自动上传；初始化失败不得把旧本地数据当作该账号的数据继续提交。
- 远程确实没有学习记录时，用有效空进度覆盖本地。网络失败、服务异常、结构不合法或不支持的数据版本不能当作“远程空进度”。
- 登录界面说明“登录将使用账号的远程数据替换当前进度”。不做数据合并或自动补传游客进度。
- 服务断开、请求超时、代理空响应或非 JSON 响应显示对应中文提示；不向用户展示 JSON 解析异常，保留原本地数据。

### 4.4 同步数据

| 数据                                               | 处理方式                                                                |
| -------------------------------------------------- | ----------------------------------------------------------------------- |
| `cards`、`bookmarks`、`days`、`typing`、`mistakes` | 随快照整份同步。                                                        |
| 进度 `version`、`datasetId`                        | 随快照传输并校验，保留现有进度版本 2。                                  |
| 学习与界面偏好                                     | 同步现有 `Settings` 中除 `dataset`、`onboarded` 外的字段。              |
| `session`                                          | 只在当前设备保存，远程快照固定为 `null`；从远程替换后清除当前活动会话。 |
| `dataset`、`onboarded`                             | 留在本机管理，不用远程设置切换到私有词库或重复显示新手引导。            |
| 词库正文、图片、音频、缓存和设备提示标记           | 继续使用现有静态资源及本机缓存，不作为用户数据上传。                    |
| 密码和登录凭证                                     | 不进入进度快照、本地备份或普通应用日志。                                |

- 快照读取和写入都要检查结构、字段类型、数值范围、版本与词库 ID；服务端独立校验，不能只信任客户端。
- 现有 `sanitizeProgress()` 对错误版本会返回空进度，不能直接用这一降级行为判断远程数据有效。必须先区分合法空快照与无效响应。

### 4.5 自动上传与手动获取

- 已确定：登录后的数据变更自动上传，并保留手动从远程获取。
- 本地仍按现有机制立即更新、短延迟保存；远程上传在最后一次同步字段变更后防抖 2 秒触发。
- 上传只由真实的本地业务变更触发；远程覆盖、登录初始化和跨标签页接收状态不应原样触发回传。
- 同一时间只上传一份快照。上传过程中继续发生变更时，在当前请求完成后上传最新快照，不能把较早请求成功误报成全部数据已同步。
- 上传失败时保留本地数据与待上传标记，显示“有数据待上传”；网络恢复、后续变更或点击重试时继续尝试。页面关闭时只能保证尽力保存本地，不能宣称远程上传必定完成。
- 手动获取先暂停自动上传并处理当前在途请求，再读取远程最新数据；成功后替换本地、清除待上传标记与活动会话，然后恢复同步。获取失败则保留当前本地进度。
- 手动获取会放弃当前未上传的本地变更，按钮旁明确说明覆盖效果；存在待上传内容时，在执行前说明该影响。
- 登录状态下导入备份、主动清空记录属于用户修改，也应自动上传；退出登录时的清空属于身份切换，不得上传空进度。
- 同步状态保持简单：未登录、本地有待上传、上传中、已同步、同步失败或需要重新登录。

### 4.6 页面刷新、离线和并发

- 持久化当前账号、对应本地进度、已知远程版本与待上传标记；刷新后先恢复本地，再校验服务端登录状态。
- 刷新恢复已有登录状态与主动点击“登录”分开处理：本地有待上传数据时不能先下载覆盖，而应在身份有效后按已知版本重试上传；无待上传内容时获取远程最新数据；版本未变化则保留本机活动学习会话，避免刷新后丢失正在做的题。
- 离线时保留已知账号的本地学习能力并记录待上传内容，恢复网络后先核实身份再同步；身份尚未核实时不上传。
- 远程快照带一个服务端递增 `revision`。上传携带读取时的 `baseRevision`，服务端仅在版本一致时原子替换并递增版本。
- 其他设备已修改导致版本不一致时返回 `409 DATA_CONFLICT`，保留本地数据、暂停自动覆盖，提示“远程数据已更新，请从远程获取”；不自动合并，也不静默覆盖远程。
- 会话失效时停止自动上传，保留本地进度并提示重新登录；用户主动重新登录仍遵循远程覆盖规则，界面说明未上传内容不会随登录补传。

### 4.7 退出登录

- 已确定：退出后清空当前进度，进入空白游客模式，不恢复登录前的游客记录，远程已保存数据保留。
- 退出前先停止同步调度并完成待上传数据；上传失败时允许重试，或由用户明确选择放弃未上传内容后继续退出。
- 退出接口成功后清除当前账号身份、账号本地进度、待上传状态及旧游客进度，创建空白游客进度；偏好设置保留，不重复新手引导。
- 退出请求失败时保留当前身份与数据，显示可重试状态，不提前宣称远程会话已注销。
- 清空范围包括卡片、收藏、日统计、打字记录、错词和活动会话；静态词库及媒体缓存不属于学习进度。
- 身份变更使旧请求回调失效，并通知同一浏览器其他标签页停止该账号的同步，避免退出后旧请求恢复界面或上传空快照。

### 4.8 账号与服务设计

- 沿用现有 Express 工程和响应格式，不另建一套服务。
- 用户名去除首尾空格并做唯一性处理；使用 3–32 位字母、数字、下划线且不区分大小写。密码保留原样，长度 8–128 位，使用 Node.js `crypto.scrypt` 加随机盐保存哈希。
- 使用服务端持久化随机会话令牌和 `HttpOnly` Cookie，退出时使该会话失效；本期无需 JWT 刷新令牌体系。Cookie 的生产配置使用 HTTPS、`Secure` 及合适的 `SameSite`。
- 优先通过同源 `/api` 反向代理访问 Express；开发环境增加 Vite API 代理。跨源部署时显式配置允许来源及携带 Cookie，不能只依赖当前 CORS 配置。
- 写接口校验允许的来源和 JSON 请求类型，注册、登录接口限制频率；服务端从登录会话确定用户 ID，不信任客户端传入的数据所有者。
- 使用用户指定的 MySQL，采用三张表；本期无需 Redis、ORM 或消息队列。正式数据库连接与部署配置由运行环境提供。

| 表              | 最小职责                                                           |
| --------------- | ------------------------------------------------------------------ |
| `users`         | 用户 ID、唯一用户名、密码哈希、创建时间。                          |
| `auth_sessions` | 令牌哈希、用户 ID、过期时间；支持刷新页面保持登录和退出失效。      |
| `user_data`     | 用户 ID + 词库 ID 唯一，保存 JSON 快照、递增版本及服务端更新时间。 |

| 接口                       | 行为                                                                             |
| -------------------------- | -------------------------------------------------------------------------------- |
| `POST /api/auth/register`  | 接收用户名、密码和初始快照，原子创建账号、数据及会话；返回用户与已保存快照版本。 |
| `POST /api/auth/login`     | 校验密码并建立会话，返回用户及远程快照，客户端据此覆盖本地。                     |
| `POST /api/auth/logout`    | 注销当前登录会话并清除 Cookie，不删除远程学习数据。                              |
| `GET /api/auth/me`         | 查询当前登录用户，用于刷新后的身份校验。                                         |
| `GET /api/sync/:datasetId` | 返回当前用户指定词库的快照、`revision`、`updatedAt`。                            |
| `PUT /api/sync/:datasetId` | 接收 `baseRevision` 和完整快照，校验归属与内容后原子替换；返回新版本。           |

- API 沿用 `{ success, data }` 和 `{ success: false, error, requestId }` 的现有约定，区分输入错误、凭据错误、未登录、用户名重复及版本冲突。
- 所有账号和同步响应使用 `Cache-Control: no-store`，客户端请求同样禁止缓存，Service Worker 显式绕过 `/api/`；升级时调整缓存版本，移除旧缓存中的 API 响应。
- 保留现有请求体大小限制，并通过实际最大用户快照核对限制；不把备份导入允许的 30 MB 误当作远程接口已支持的大小。

## 6. 验收标准

以下作为当前实现的行为标准；验证范围见第 7 节。

1. 未登录完成学习、收藏和打字练习，刷新后本地进度保留；远程不可用时仍可使用，且不产生用户数据上传。
2. 游客已有 20 个词的学习记录，注册新账号后账号远程数据包含这些记录；另一设备登录该账号能获取相同记录。
3. 本地游客有 20 个词、已有账号远程有 5 个词，登录后本地使用远程的 5 个词，远程没有混入游客记录。
4. 已有账号的远程进度合法为空时，登录后使用空进度；登录或数据请求失败时，原本地记录保持，不能被错误清空或上传。
5. 登录后完成一道题或修改同步偏好，本地立即生效，防抖后自动上传；连续修改以最新快照为准，已同步状态与实际保存版本一致。
6. 断网期间学习后刷新页面，待上传内容仍在；恢复网络且会话、远程版本有效时可以继续上传，不被启动时的远程获取覆盖。
7. 手动从远程获取成功后，本地内容与远程一致、活动会话清除；获取失败时保留本地；远程覆盖本身不触发回传。
8. 两台设备基于同一版本修改，第一台上传成功后第二台的旧版本被拒绝；第二台本地数据保留，远程不会被静默覆盖。
9. 退出后学习记录为空、游客可继续学习，远程记录保留；重新登录可恢复远程记录，退出导致的空进度没有上传。
10. A 退出后 B 登录只能看到 B 的远程数据；其他标签页、延迟请求和被缓存的响应不能把 A 的数据带回。
11. 用户名重复、密码错误、无登录态上传、畸形快照、词库不匹配和不支持的版本都明确失败，不修改已有远程数据。
12. 注册和登录不出现邮箱、验证码或找回密码；刷新可恢复有效登录，退出后原会话失效，密码不以明文保存。
